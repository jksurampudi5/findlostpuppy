# Local Android testing and production access

Keep changes on the current branch. Do not commit, push, or upload a release until the owner approves it.

## Browser checks

Start `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort` and review http://localhost:5173.

Run:

```sh
npm run build
node scripts/test_responsive.mjs
node scripts/test_mobile_interactions.mjs
node scripts/test_location_accuracy.mjs
```

The responsive script checks eight routes at 320, 390, 768, and 1024 CSS pixels. Screenshots and results go to ignored `scratch/responsive-audit/`. It uses a temporary browser profile, synthetic local data, and blocks external requests. It checks layout, not real authentication, cloud synchronization, or GPS. Set `CHROME_PATH` if Chrome is installed elsewhere. Optional `AUDIT_WIDTHS`, `AUDIT_ROUTES`, and `AUDIT_OUTPUT` narrow a follow-up run.

## Installed emulator

This Mac already has the Android SDK at `/opt/homebrew/share/android-commandlinetools` and the `FindLostPuppyTest` Android 14 / API 34 ARM64 virtual device.

```sh
/opt/homebrew/share/android-commandlinetools/emulator/emulator -avd FindLostPuppyTest -no-snapshot-save -no-audio
```

Build and install the debug app:

```sh
npm run build:android
npx cap sync android
cd android
./gradlew assembleDebug
cd ..
adb -s emulator-5554 install -r android/app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 shell am start -n com.findlostpuppy.app.debug/com.findlostpuppy.app.MainActivity
```

Debug uses `com.findlostpuppy.app.debug`; the Play Store application keeps `com.findlostpuppy.app`. They have separate local data and can coexist. The emulator runs bundled files, so rebuild and reinstall to see later changes. Localhost updates automatically.

Before release, also test the signed build on a physical phone and Android 15/16: system bars, keyboard visibility, back navigation, camera/photo selection, location permission denial and approval, sign-in, account deletion, and owner/pet/sighting flows. These are not covered by the local layout audit. Never use real public pet reports as test fixtures.

## Production access

The supplied Play Console screenshot showed 7 opted-in testers and a disabled production application button. The closed release requirement was complete; the 12-tester and 14-day requirements were not.

Recruit at least 5 more opted-in testers and keep at least 12 opted in continuously for 14 days. Collect real feedback and record fixes. Emulator checks do not replace the closed test. Once Play Console enables **Apply for production**, answer the testing and readiness questions using the actual test results. Approval and publication are separate steps; no publication date is guaranteed.

Reference: [Google Play testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465).

No release AAB is generated by the commands above. When preparing a release later, verify the latest Play version code, increment it, and follow AGENTS.md's versioned Desktop bundle naming rule.
